# GTM-NL6K22CM — Phase 0 configuration checklist

> **Phase 0 covers the marketing site only.** The pay link, customer quote, manage-booking
> and Ride Board properties shipped afterwards and have their own events, consent path and
> console steps — see **[`property-tracking.md`](property-tracking.md)**, which extends this
> checklist rather than replacing it. Do that one too, or those four properties stay dark.

Do this in the Google Tag Manager + GA4 web UI. The site code already pushes all events
below to `dataLayer`; these steps turn them into tags. Reuse the EXISTING container/property.

## GA4
- [ ] GA4 Configuration tag → Measurement ID `G-XEW62ZD7B3`, trigger: Consent Initialization.
- [ ] Mark `purchase` as a **key event** (Admin → Events).
- [ ] Register custom dimensions (event-scoped): `payment_type`, `name` (checkout step),
      `item_category`, `source`, `mode`, `freetext_place`.
      `freetext_place` (on `search`) is `none` / `from` / `to` / `both` — which ENDS of the
      search arrived as a free-text place rather than a catalogue id. It answers "is it worth
      geo-matching a pin to a scheduled stop?", and it is deliberately not the place name:
      `to` itself would blow past GA4's ~500-distinct-values-per-day `(other)` bucket. **GA4
      does not backfill** — every day this is unregistered is a day that question stays
      unanswerable.

## WhatsApp contact tracking (added 2026-07-30)

`analytics.js` fires **`contact_whatsapp`** on every click of a `wa.me/<number>` link,
plus search.js's programmatic 6+ pax handoff. Params: `method` (`whatsapp`), `link_id`
(the anchor's id, `''` if unset), `page` (pathname). No phone number, no href, no PII.

- [ ] GA4 event tag → Custom Event trigger on `contact_whatsapp`, params `method`,
      `link_id`, `page`. Requires `analytics_storage`.
- [ ] Register `link_id` and `method` as event-scoped custom dimensions.
- [ ] Mark `contact_whatsapp` a **key event** — for a WhatsApp-first business this is a
      conversion, not an engagement signal.

**Do not** trigger on all `wa.me` clicks. board.js builds phone-less `wa.me/?text=…`
links for travellers sharing a van with a friend; those are shares, not contacts, and the
site code already excludes them. A broad `Click URL contains wa.me` trigger in GTM would
put them straight back in and inflate the metric with the board's own virality loop.

## 2026-09-20 audit — 21 of 31 emitted events had no tag

Audited the **published** container (`gtm.js?id=GTM-NL6K22CM`) against every `chTrack` /
`track` / `ev` call site. The site emits **31** events; **21** reached `dataLayer` and were
discarded. GA4 does not backfill, so that data is gone, not delayed.

Tagged and live: `search`, `view_item_list`, `select_item`, `begin_checkout`, `checkout_step`,
`add_payment_info`, `purchase`, `view_item`, `exception`.

**[`gtm-missing-tags.json`](gtm-missing-tags.json) covers the other 20** — generated by
`tools/analytics/build-gtm-missing-tags.mjs`, same shape as the ride-board import that worked.
(`ch_context` is the 21st and is deliberately untagged: it labels the session, it is not an
event.) Each tag carries a `notes` field saying why it earns its place.

### Import it

1. GTM → Admin → **Import Container** → choose the file.
2. Workspace: **Existing** → Default Workspace. Merge option: **Merge → Rename conflicting
   tags** (nothing should conflict; the audit excluded everything already live, and a test
   pins that).
3. Review the preview: **20 tags, 20 triggers, 21 variables**, no deletions.
4. **Preview** and walk one real booking before publishing.

### Then, in GA4 (the import cannot do these)

- Mark **`contact_whatsapp`** a key event. For a WhatsApp-first business it is the conversion.
- Register the new params as event-scoped custom dimensions, or they show as `(not set)`:
  `reason`, `state`, `status`, `has_balance`, `link_id`, `method`, `page`, `which`, `km`,
  `extra_km`, `new_value`, `surface`, `estimate_state`, `material`, `route_fingerprint`,
  `leg`, `tries`.
- **Admin → Data streams → Configure tag settings → List unwanted referrals → add
  `payhere.lk`.** Without it the customer returns from the payment gateway as a NEW session
  sourced `payhere.lk / referral`, and PayHere is credited for sales that came from Google or
  Instagram. Two minutes, and it silently distorts every acquisition report until done.

`web-tests/unit/gtm-event-coverage.test.js` fails if a new event is added to the site without
being tagged or explicitly listed as deliberately untagged — verified by adding a probe event
and watching it go red.
